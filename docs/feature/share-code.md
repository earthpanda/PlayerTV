## 目标与范围

**状态：同机播放源交接已实现、待验证。** 用户希望 PlayTV 引入分享码，分享内容可能是应用，也可能是播放源；本次已确认并实现的范围见上节。下方的跨设备查询、清单和应用安装仍是待确认草案，不能据此声称已经实现。

分享码用于定位一份分享内容，而不是把播放地址或 APK 文件本身编码进几位数字。建议同一个分享码可以包含多个条目，条目分别标识类型，用户选择后执行对应操作。是否允许混合内容待确认。

参考实现现为六位本机码，映射到本机保存的链接；未命中的码仍进入默认应用列表。码不包含链接内容，也没有可供其他设备查询的服务。

## 建议的用户流程

```text
进入分享码 → 输入并提交 → 查询对应分享内容 → 展示清单
                                      ├─ 应用：选择 → 下载 → 系统安装
                                      └─ 播放源：选择 → 解析 → 播放或保存
```

1. 用户通过遥控器输入分享码并提交。码的长度、字符范围、是否输满自动查询、入口及界面设计待定；不先假定为四位数字。
2. 客户端把码交给已配置的查询服务或清单，取得匹配结果；不存在、已失效、网络失败、响应无效分别反馈，不用固定列表冒充查询成功。是否允许离线缓存及缓存有效期待定。
3. 展示分享名称及可识别的条目类型、名称和可用状态。未知或不支持的类型应提示并禁止执行，不妨碍浏览其他有效条目。空清单与查询失败区分；重复名称通过稳定条目标识区分。
4. 用户主动选择一项后才开始下载或解析；查看清单不自动安装应用、不自动覆盖已有播放源。多项批量操作、排序及取消后保留结果的细节待确认。

## 内容处理

### 播放源

分享内容可指向播放地址、播放列表或来源配置；具体支持格式以实际解析能力为准，不把所有 URL 都当成可播放视频。用户选择后复用现有来源发现、候选列表和播放流程，保留解析中、部分结果、空结果、解析失败和取消的区别。是否立即播放、何时保存历史、同一来源重复导入如何处理，需按产品决策与现有存储契约明确，不静默覆盖历史。

现有 [SourceRepository](../../model/src/debug/java/com/ai/playtv/model/repository/source/SourceRepository.kt) 能发现网络地址、仓库及部分列表和 JSON 引用；[ImportedSource](../../model/src/debug/java/com/ai/playtv/model/bean/domain/source/ImportedSource.kt) 定义候选条目及当前单来源上限。它们位于 `debug` 源集，属于技术预览；正式功能要先确定是否迁移以及正式入口，不能假定 release 已具备这些能力。发现部分结果也不代表所有频道可播放，最终播放仍取决于来源和设备。

### 应用

建议展示应用名称、下载状态等可用信息；用户选择后才下载，完整性校验通过后通过受限的 content URI 交给系统安装器，由用户在系统界面确认。系统不支持、授权不足、用户取消、下载或校验失败都须有明确状态；回到应用时重新核对系统实际安装状态，不能仅凭启动安装器就显示安装成功。已安装应用的识别与打开方式、下载进度、重试、取消、缓存保留以及安装包来源可信度待详细设计。

APK 内容来自外部，单靠从同一清单获取的摘要只能发现传输损坏，不能独立证明发布者可信。若需要验证来源，必须另行确定可信清单的分发方式及签名或可信证书策略。Android 版本、targetSdk、安装授权及系统安装器可用性须在实现时核对；不预设已有安装或下载公共能力。

## 分享码与内容契约（建议，非已存在接口）

建议将**码解析**与**内容执行**分开：查询层只负责将码解析为版本化的清单；各内容类型分别由现有播放源处理链或未来应用下载/安装链处理。清单概念上包含：协议版本、分享标识和名称，以及包含稳定条目标识、类型、名称和该类型所需地址/校验信息的条目列表。具体字段、错误码、地址、大小限制、顺序和版本兼容策略由服务协议确定，不预设 API 已存在。

| 事项 | 可选方向与影响 | 状态 |
|---|---|---|
| 分享内容如何创建 | 管理者维护远程静态清单；或用户创建并由服务保存、分配码 | 待确认 |
| 码的范围 | 数字码便于遥控器输入；位数越短容量越小且更易被枚举 | 待确认 |
| 可见性 | 公共分享；或需要独立访问控制的私密分享 | 待确认；短数字码不能视作保密凭证 |
| 生命周期 | 长期有效；或按时间、撤销状态等失效 | 待确认 |
| 修改语义 | 码指向可更新清单；或指向创建时固定快照 | 待确认 |
| 支持的内容 | 单一类型或混合应用、播放源；每码和每条大小上限 | 待确认 |
| PlayTV 范围 | 只接收和使用；或同时提供创建、编辑、撤销分享 | 待确认 |

如果未来开放用户创建，服务端还需负责码唯一性与冲突处理、访问限制、修改/撤销权限、有效期、滥用控制及创建失败重试等；客户端生成一个随机短码本身不能保证全局唯一。清单与源地址可发生变化，查询成功也不保证下载或播放成功。

## 状态、并发和生命周期

- 查询区分输入、查询中、结果、空结果、码无效或失效、网络/服务失败、协议不支持与取消；具体提示和视觉状态待设计。允许重试时保留必要输入；旧请求返回不得覆盖新的查询结果。
- 单个条目的下载、安装、解析状态独立于清单状态；一个条目失败不自动清除其他条目。重复点击应避免重复启动同一动作；多个任务是否并行及页面退出后是否继续待确认。
- 页面、任务和缓存的所有者须在实现前确定。配置变化可以恢复必要的输入与可重建状态，但不能重复执行安装或导入；进程重启后的恢复能力按最终任务设计决定。
- 按 [UI 生命周期](../rule/android-ui-lifecycle-rules.md) 处理遥控器焦点、键盘和返回；布局、入口、焦点与系统返回具体行为，以及组件选择、设计资源和中英文文案待确认。当前无本功能设计稿或资源，不能假定已有正式界面。
- 若仅做页面内查询和下载，不预先引入后台 Service 或通知；是否需要跨页面/重启继续由最终需求决定。网络、数据分层与文件处理遵循 [网络请求](../rule/network-request-rules.md)、[数据契约](../rule/data-contract-rules.md) 和 [存储规则](../rule/file-storage-rules.md)。

## 存储、权限和隐私

分享清单、下载临时文件、已导入来源和播放历史分别定义真源及保留期；取消或清理仅处理本任务拥有的临时文件，不删除已有来源。是否缓存清单、允许离线使用、导入后更新及去重策略待确认；持久化方案和迁移不能提前假定。

播放源 URL 和分享内容可能包含令牌或个人信息，日志和错误展示不应输出完整地址、码或响应正文。访问外部内容前须有边界、超时和大小限制，并处理重定向及不受支持的地址；具体网络访问范围由产品使用场景确定，不能假定所有地址都可信或可达。

安装包下载优先使用应用私有空间；交由系统安装使用范围受限的 URI 和临时读取授权。实际 Manifest、系统版本、安装授权、拒绝/设置返回行为及缓存回收时机在实现前按 [权限规则](../rule/permission-rules.md) 核对。

## 影响与验收

现有基线是 debug 来源入口直接提交地址、通过来源发现会话进入播放，历史存储和本地搜索使用已有数据；分享码目前不存在。引入时应保持直接输入地址、现有解析、播放、历史与搜索路径，除非后续需求明确改变。现有未提交改动和现有验证状态以对应功能文档及工作区为准。

实现后需覆盖：不同有效码返回不同内容、无效/失效码、空清单、网络/协议错误、重复提交与迟到响应；同一清单内不同类型和未知类型；源解析成功、部分结果、失败、取消、重复导入与既有播放/历史回归；下载中断、校验失败、系统安装取消或失败以及真实安装状态核对；遥控器焦点、返回、配置变化、退出与恢复。以实际设备、构建版本和测试结果记录证据，不能把静态阅读当成运行验证。
