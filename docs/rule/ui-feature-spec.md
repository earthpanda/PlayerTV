# Feature Spec 字段模板

生成前完整阅读项目约定与 [业务开发规则](business-development-rules.md)，其他必读项按 AGENTS.md 的触发条件选择。下面的字段在实际功能 Spec 中填写；本文件不是一个已经确认的业务需求。

- `[AUTO]`：从项目约定、能力目录和已有授权取值，不重复问。
- `[INFER]`：来自 MCP/接口/schema，标记推断待确认；静态设计不能决定业务。
- `[ASK]`：仅汇总上下文尚未确定的业务项，同类合并，一次不超过 8 项。
- 字段缺失不能自行发明业务；视觉参数从 MCP/设计系统读取，不因 Spec 未抄尺寸而阻塞。本地资产缺失独立按项目约定停止。

| 章节 | 必须说明 |
|---|---|
| 目标与范围 | 当前/待实现状态、用户目标、边界、依据 |
| 设计与资产 | fileKey/nodeId、所有状态变体、公共组件候选与同名本地资产检查 |
| 承载与导航 | Activity/Fragment/Dialog 等实际能力、入口参数、出口结果、返回/取消行为；技术样例说明 main/debug 源集、启动方式及 release 是否包含 |
| 状态 | 每个状态的触发、数据依据、UI/可操作范围、对应设计或已存在的默认皮肤 |
| 公共反馈 | 按组件目录的场景 ID/常用说法选首屏/刷新/操作/局部加载、短暂消息、确认或设置引导；记录真实入口和调用例、已有/待补、阻塞与取消、并发归属和样式替换。不涉及写不涉及，不要求用户记类名 |
| 交互 | 事件、前置校验、数据动作、业务成功判定、失败/取消/迟到结果与防重复策略 |
| 数据契约 | 数据来源、接口/本地方法、字段有效性、复用类型、model 中 Contract 与独立数据文件完整路径 |
| 封装边界 | 按数据契约判定职责、可写事实与所有者；已有实现/先例的实际路径、复用部分和差异，查无结果如实写明；SDK 技术与业务含义边界；触发结构复核时记录结论。已有规则可直接链接，不重复抄写 |
| 网络与图片 | 按网络/图片规则复用默认链路；列出配置、Service、DTO、Repository、Mapper、Contract、组装入口和图片绑定的实际文件路径，缺少的公共能力另列；只填写本功能的协议/图片差异，不重复技术选型 |
| 并发与恢复 | 各动作的替换/串行/并行策略，请求代次、幂等、迟到回调，配置变化/进程死亡后恢复哪些事实 |
| Manager 与资源 | 持有者、作用域、依赖组装、初始化失败、关闭/取消及账号/环境切换；无长期资源则写不涉及 |
| Android Service 与通知（选填能力） | 有需求时按 [Service 与通知](android-service-notification-rules.md) 及其源码参考，说明单/多 Service、共享通知协调器、任务与连接所有者、系统类型/实际运行确认、通知身份/操作/点击、拒绝与结束恢复；仅普通通知时填写其范围；无需求写不涉及，不生成 Service 或默认初始化 |
| 存储与文件 | 数据真源、账号/环境作用域、目录/KV/schema、Uri 授权、备份/迁移、保留/容量及清理范围；无持久化则写不涉及 |
| 权限与系统能力 | 用户动作、系统版本/targetSdk 条件、最小权限、部分授权/拒绝/设置返回、操作恢复和取消；不申请则说明采用的系统入口或不涉及 |
| 生命周期与导航 | Binding/订阅/弹窗/键盘/Insets 的所有者、释放和返回结果，页面离开后哪些工作继续 |
| 非功能差异 | 语言/时区/单位、无障碍、敏感信息与诊断、不支持项；不重复其他章节已说明的内容 |
| 变更影响与回归验证 | 按 [AGENTS 最高优先级准则](../../AGENTS.md#最高优先级变更正确性与旧行为保护)，列明改前基线、允许改变/必须保持的行为、共享链路与调用方、已知问题；必要局部重构的职责/契约边界；新旧行为对应的验证方法、对象/版本、实际结果与证据位置、未执行项及原因。按影响选取，不机械全量测试，不把历史通过写成本轮通过 |
| 完成状态 | 实际文件、最终差异与人工复核、确定性检查及回归结论；区分实现完成与验收完成，明确失败/阻塞和仍未覆盖的边界，不能只凭新功能可用或编译成功宣称无回归 |

首屏失败、刷新失败、分页失败和已有内容保留不能笼统合并；HTTP 调用成功不等于业务成功。列表默认机制不决定每页条数、游标或排序。流式返回需定义追加/替换、结束、取消和部分结果保留。

按功能查阅 [网络请求](network-request-rules.md)、[图片加载](image-loading-rules.md)、[Manager](manager-lifecycle-rules.md)、[存储](file-storage-rules.md)、[权限](permission-rules.md)、[UI 生命周期](android-ui-lifecycle-rules.md) 和 [公共能力](common-capability-rules.md)。直接链接已有规则，不在每个 Spec 抄一份；只填写本功能的选择、差异和真实实现路径。“不涉及”不能掩盖实际使用的文件/权限/后台任务。

没有设计/接口的技术模板样例可明确“不涉及”；真实业务不能用技术样例的假设补齐。未填写 ASK 的功能 Spec 不能进入对应业务编码。
