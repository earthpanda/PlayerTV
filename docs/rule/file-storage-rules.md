# PlayTV 文件、KV、数据库与数据清理规则

本文件负责本项目持久化选型、路径、作用域、读写、迁移和清理。模块职责见 [数据契约](data-contract-rules.md)，权限判断见 [权限规则](permission-rules.md)。实际存储实现与选型见 [组件目录](ui-component-catalog.md) 和 [项目基线](project-context.md)，不能把以下约束当作已提供的工具 API。

## 先确定数据归属，再确定路径

每类持久化在功能 Spec 记录：数据所有者、用途、是否可重建、是否敏感、保存位置、保留/容量策略、备份策略、退出/切号/清缓存/注销时的行为。没有账号的项目可只有安装级作用域，不强塞登录系统。

| 数据 | 优先位置/机制 | 约束 |
|---|---|---|
| 可重建图片、转换中间文件 | cacheDir；确有必要再用 externalCacheDir | 可能被系统清理，不作为唯一数据源；外置位置可能不可用 |
| 不可丢的应用私有文件、草稿附件 | filesDir；按需求考虑 noBackupFilesDir | 生命周期与备份明确，不能因“清缓存”丢失 |
| 应用专属外置大文件 | getExternalFilesDir | 可空、介质可失效；不当作用户永久导出目录 |
| 用户选择导出/共享媒体 | SAF CreateDocument / MediaStore 等 | 按当前系统和文件类型选择；写入成功后才宣布导出成功 |
| 用户选择导入 | 系统文档/照片选择器返回的 Uri | 用 ContentResolver 读，不强行解析成真实绝对路径 |
| 小型设置、开关、上次筛选 | 职责内聚的键值存储 | 不承载大列表、文件内容或需要事务的关联数据 |
| 可查询实体、关系、离线任务 | 数据库 | schema、索引、事务、迁移和作用域明确 |
| 登录凭据等秘密 | 专门的凭据存储方案 | 按威胁模型选择 Keystore 支持的保护，日志/备份排除；普通 KV 不自动等于安全存储 |

本模板新项目默认 KV 方案为 MMKV，推荐初始化启用 `mmkv`；依赖和 API 以 [依赖目录](build-dependency-catalog.md)、组件目录和真实源码为准。已初始化项目的 DataStore 不自动替换/清空，新增数据沿已确认方案；迁移必须明确旧数据映射。不用 KV 代替数据库/文件/凭据存储。公开 API 表达业务含义，不让页面到处直接操作字符串 key 或数据库 DAO。

## 固定 KV 实现链路

- `support/storage/mmkv` 只负责引擎、typed key、固定 StorageScope、租约与技术错误；model 的 `storage/<feature>/<Feature>Store` 定义 key/类型/版本/默认值及 IO/序列化，具体目录唯一维护在数据契约。
- Application 的 AppContainer 初始化 MmkvStorage；Store 动作在 IO 打开固定 scope 的租约并 use，或由所属容器打开后复用并关闭。不能在页面直接初始化 MMKV，不能关闭其他功能仍在使用的 native 实例。
- ViewModel 调用语义 Store，成功后更新 State；跨页面需观察设置时由同作用域共享的 Store 持有只读 StateFlow，先读取成功再标 ready，写成功后再发布。原始 MMKV 没有本基线承诺的跨进程/外部写入 Flow，不伪造自动通知。
- key 缺失、合法空值、读失败分开；同名类型永久不变，schema 变化用新 key/迁移。普通设置有明确业务默认值，解析失败不能直接套默认值掩盖损坏。
- 基线 noBackup、SINGLE_PROCESS、字符串 64KiB 上限，无自动清文件/凭据加密/多 key 事务。启用时生成 `docs/template-capabilities/mmkv.md`，包含技术样例及存取 API；未启用时先核对组件目录，不调用不存在文件。

## 作用域与命名

- 统一路径提供者管理目录；文件基础操作归 base，用户/环境隔离规则与业务文件组织归 model，SDK 存储适配归 support。不同职责不能堆在同一个 FileManager。
- 有多账号/多环境时，缓存、数据库、KV、附件索引都按相同作用域隔离，例如 `环境/用户作用域/功能/任务ID`；作用域是稳定内部标识，不使用手机号、邮箱或访问令牌作目录名。
- 任务开始时捕获作用域及输出所有权，整个任务始终使用该快照。切号后禁止把旧结果写入“当前用户”目录。
- 不硬编码 `/sdcard` 或安装目录。持久记录优先保存相对路径/业务文件 ID；Uri 的授权有效性另行管理。重新读取时检查文件仍存在且属于当前作用域。
- 文件名使用内部 ID/随机任务 ID 防冲突，扩展名来自受控类型；展示名与真实文件名分开。时间戳单独作为唯一性依据不足。
- 用户输入/服务端文件名不能直接拼路径；限制路径片段，拒绝绝对路径与 `..`，检查规范化后路径仍在预定根目录内。删除、解压和覆盖同样检查，避免跨目录及符号链接越界。

## 读写、复制与并发

- 阻塞读写在 IO 执行，使用 `use` 关闭流；大文件流式处理，不把整个音视频读进内存。明确编码、覆盖/追加语义、容量限制与取消行为。
- 必须保留旧版本的文件使用同目录临时文件写入，成功后再按平台保证替换；私有小文件可评估 AtomicFile。原子替换仅覆盖文件更新本身，不自动保证文件+数据库+网络一致。
- 同一目标只有明确的写入者，或显式加锁/排队；每个任务有自己的临时文件，取消/失败仅清理自己拥有的产物。创建新图片时不得删除整个公共 temp 目录。
- 检查目录创建、可用容量、流打开、写入/关闭和最终提交失败；不能 `catch` 后仍返回成功路径。跨存储复制在确认目标完整前保留源文件。
- 文件和数据库联合更新说明次序、失败补偿及启动时的孤儿文件核对；无事务支撑的两个写操作不能宣称整体原子。
- 输入 Uri 可能大小未知、权限过期、格式与 MIME 不一致。按读取字节数限制上限；不要相信展示名/扩展名。需要持久访问时，仅在 provider 和返回标志支持时获取持久授权，否则按需求复制到私有目录。

## 导入、分享与下载

- 应用私有目录不因普通读写而申请广泛存储权限。分享使用范围受限的 FileProvider/content Uri 和临时读授权，不发送 file://，不配置暴露整个根目录的路径。
- 相机/导出先创建本任务输出，再执行外部动作；用户取消清理空产物。分享后的文件不能立即删除，应按接收方读取时机和保留策略回收。
- 下载区分部分文件与完整文件，完成后提交；断点续传需验证远端版本及 Range 支持，不能把两个不同版本拼接。上传/下载是否跨重启、如何取消和重试写入 Spec。
- 应用私有外置目录卸载时会被移除；“让用户永久保存”需要真正的用户导出位置，不能只 Toast 一个私有绝对路径。

## KV、数据库与迁移

数据库的目录、IO/Flow 展示、事务快照、schema、版本合并、outbox 和后处理统一见 [数据库与同步规则](database-sync-rules.md)。禁止主线程查询不影响实时展示：UI 观察已提交的数据库结果。

- 按功能定义有类型的存取入口，集中维护 key、默认值、版本和作用域；区分“不存在”“合法空值”“解析失败”。不建立汇集所有业务字段的巨型 KVManager。
- 序列化字段和持久化枚举用稳定协议，重命名类/字段不等于数据迁移。新增版本明确向前兼容、升级、损坏恢复与降级策略；不能读取失败就无条件清空全部数据。
- KV、数据库、文件缓存各自只有清晰的数据真源，避免互相复制后无失效协议。多字段一致更新需要事务或明确提交标记；多进程访问需要所选实现明确支持。
- 缓存定义 key（含账号/环境/参数/版本）、有效期、容量和失效条件；磁盘过期使用可持久时间，进程内间隔使用单调时钟，不能混用。
- 数据库按需索引和事务，不默认 destructive migration；迁移或清理失败要可诊断。Android 备份/设备迁移是否包含数据库、文件、KV/凭据必须按当前项目明确配置，不能依赖默认值猜测。

## 清理是业务动作

| 动作 | 必须确认的范围 |
|---|---|
| 清缓存 | 仅可重建数据；保留草稿、未上传文件、当前任务、账号设置 |
| 切换账号 | 隔离旧作用域并关闭旧实例；是否保留旧数据由产品决定 |
| 退出登录 | 清失效凭据和会话资源；离线内容保留规则单独规定 |
| 注销/删除用户数据 | 核对远端结果、全部本地副本、备份/导出边界及失败补偿 |
| 定期回收 | 只扫描受控目录，按容量/时间及活跃任务保护清理，避免启动主线程遍历 |

清理入口列出可删除目录/key/表，并返回部分失败，不能一个 `deleteRecursively()` 清整棵应用目录。自动清理的授权和保留策略写入功能；开发工具删除文件仍遵守 AGENTS。
