# PlayTV 工具类、扩展函数与公共能力规则

本文件负责本项目如何发现、设计和交付公共能力。模块归属只在 [数据契约](data-contract-rules.md) 维护；已实现能力只在 [组件目录](ui-component-catalog.md) 登记，项目选择见 [项目基线](project-context.md)。下表是实现候选与契约要求，不是当前可调用 API。

## 先复用，再决定封装形式

查已有实现和无先例时的讨论顺序统一遵循 [AGENTS](../../AGENTS.md)，先例入口见 [参考索引](../reference/README.md)。本节只规定选定公共能力后的封装形式，不另定义职责分层。

1. 先读 [公共基础基线](common-foundation.md) 和组件目录，复用标准实现与扩展点，不重新生成同义客户端/解析器/存储器。搜索源码、AndroidX/Kotlin 和已启用工具库，确认是否已有同语义 API。已有 `isVisible/isGone` 等不再包一组同名近义扩展。
2. 无状态、与接收者紧密相关的单个操作可用扩展；跨对象转换用纯函数；可配置策略用对象/接口；持有任务/资源的行为用 Controller/服务。
3. 只有出现真实共享需求、或需要隔离平台/SDK 变化时才抽公共层。不把某页面的语言、会员枚举、状态码夹带进“通用”方法。
4. 文件按能力分组，如键盘/文本/日期/Uri，避免不断增长的 Utils.kt/ViewExt.kt。公共代码有真实调用示例，不为猜测未来需求预建空壳。
5. 用户描述公共 Loading、Toast、确认框时，从组件目录的场景与常用说法查入口，行为与构建按 [公共反馈](ui-feedback-rules.md)。已有类名不同先登记别称，不另包同义入口；新增或替换后补全场景映射及真实使用位置。

## API 必须能从名称和契约看出行为

- 写清输入、返回、空值、错误、线程、单位和副作用；`null` 不同时代表“不存在、失败、用户取消”。不能 catch 后用空串/false 掩盖所有错误。
- 查询方法只查询：`isGone` 真正判断 GONE，不能误判 VISIBLE；`exists` 不创建目录；格式化不发 Toast、不访问网络。
- UI 变更在主线程，方法不要悄悄异步 post 后让调用方误以为已完成；确需延迟的 API 写明回调/取消和生命周期。
- 不在扩展里藏全局用户、硬编码屏幕宽度、反射内部资源或业务跳转。无法确定宿主/状态时返回可解释结果，不强行 `!!`。
- 时间名带单位，如 durationMs/epochSeconds；日期处理明确 Locale/ZoneId 与格式。优先 java.time，区分时长和时刻；计时/防连点使用单调时钟。
- 数值/金额格式按业务精度和舍入约定，不默认 Double 满足货币精度。文件大小说明十进制还是二进制单位，未知值不伪装为零。
- 捕获异常的通用执行器保留协程取消，不能把所有业务塞进一个 launchIO/runCatching；取消与线程规则见 [业务开发](business-development-rules.md)。

## 常见能力怎样形成一致写法

| 能力 | 公共部分应负责 | 调用方/业务必须负责 |
|---|---|---|
| 点击节流 | 每个 View/操作的单调时间窗，明确定义首击、取消和监听所有权 | 提交锁、服务端幂等；不把节流当防重复扣费 |
| TextView 行高/样式 | 统一单位、基线、字体 padding 和真实展示效果 | 业务字号档位、语言选择；不能硬编码其他项目枚举 |
| 键盘/触摸 | 当前宿主、附着时机、Insets 和 dispose | 哪些页面自动显示、哪些区域点击收起 |
| 日期/时长/大小格式化 | 单位、语言、时区、负值/未知值行为 | 服务端时间语义与业务文案 |
| Uri/文件基础操作 | 流、IO、访问授权、受控路径和错误结果 | 文件内容、所属用户、保留和清理规则 |
| 网络封装 | 传输、超时、取消、脱敏诊断、可替换数据源 | 成功码、DTO、业务重试/鉴权策略 |
| 图片加载 | 目标生命周期、取消、缓存键与错误资源策略 | 图片来源/可见性、真实设计指定的占位与失败态 |
| KV/数据库 | 存储引擎、类型契约、版本及迁移机制 | key/schema 业务含义、作用域、缓存失效 |
| 权限/系统选择器 | 系统差异、宿主、申请结果和取消 | 使用意图、拒绝降级、后续业务动作 |
| 日志/诊断 | 等级、集中脱敏、容量/保留、版本开关 | 哪些字段敏感、是否需要用户反馈/上报及相应产品规则 |

网络与图片的具体行为分别由 [网络请求](network-request-rules.md) 和 [图片加载](image-loading-rules.md) 维护；默认技术方案及启用状态查依赖目录。不要另起一套同义工具。未交付能力先完成实现与登记，不因表中列出网络/图片/KV 就自动添加 SDK。新增依赖、配置、资源和可用 API 如实登记，不能让后续 AI 根据熟悉的库名猜调用。

## 公共能力交付要求

- 真实源码、依赖与模块方向完整；初始化、线程、关闭/取消、错误和可重入契约明确。需要 Manifest/provider/资源/R8 的一起交付，不能只给 Kotlin 文件。
- 至少有一个真实调用位置，并写明实现状态、限制和验证状态。公共签名暴露 SDK 类型时登记实际耦合和 api 依赖，不能宣称完全隔离。
- 本项目新增可选能力时，在本项目依赖目录/组件目录登记完整实现、启用条件和依赖；未启用能力不偷偷初始化 SDK、不额外索要权限、不启动后台任务。只有维护生成原型时才需要原型的 capability 元数据，日常开发不依赖外部原型目录。
- 日志避免令牌、Cookie、密码、个人文件内容与完整敏感 URL；结构化字段先脱敏，再按版本开关输出。正则兜底不等于完整保护，Crash/埋点上传不默认接入。
- 对复杂/高影响公共逻辑记录关键验证场景，如时区边界、并发同名文件、权限取消和迁移失败；实际测试遵守 AGENTS 的授权要求，不给简单转发函数堆镜像测试。

## 缺项与补齐次序

需要某项能力时先查组件目录和源码，确认已提供、部分实现或缺失；不在本文件另维护一份实现清单。

公共基础源码与可选能力的实际状态查组件目录；当前只交付基础与 src/debug 调用示例，完整请求到 UI 的功能链路另按 Spec 验证。数据库、下载器、分享和公共业务 UI 按真实功能补齐。账号、支付、蓝牙、统计等仅在真实业务需要时增加。每补一项同步真实源码、调用示例与能力登记，不能把“规则已写”当作“功能已实现”。
