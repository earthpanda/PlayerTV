# PlayTV 业务开发与异步状态规则

本文件负责本项目的业务执行、请求并发、页面状态和恢复。类型和目录归属见 [数据契约](data-contract-rules.md)，Manager 生命周期见 [Manager 规则](manager-lifecycle-rules.md)。具体适用边界见 [项目基线](project-context.md)；下文描述实现要求，不代表已经提供网络、缓存或请求协调器。

## 一条业务动作如何落地

涉及 HTTP/JSON 的具体处理和 Repository 出口遵循 [网络请求](network-request-rules.md)；运行时图片的目标绑定与失败处理遵循 [图片加载](image-loading-rules.md)。本文件继续维护通用并发与恢复规则，不重复 SDK 细则。

1. 先在功能 Spec 写出输入、前置条件、成功依据、失败/取消、重复操作和恢复策略，不能只列 UI 点击。
2. View 接收操作并派发 Event；ViewModel 校验当前交互条件、调度任务、更新 State；Repository 负责数据读取/写入及必要转换。权限弹窗、导航与字符串资源由 UI 宿主处理。
3. 按 [数据契约的角色判定](data-contract-rules.md#业务角色的唯一判定) 选择动作实现；简单数据动作直接调用 Repository，独立计算/编排可调用 Planner/UseCase，不要求经过数据源。不能为每个接口机械加一层转发。
4. Repository 的公开方法表达业务动作和结果，不暴露 ResponseBody、SDK 回调或 Activity；协议成功码、字段必填性、排序和分页约定来自当前接口。
5. 跨接口动作写明部分成功与补偿。客户端连续调用两个接口不等于事务；提交超时不等于服务端未执行，重试前按协议查结果或复用幂等键。

## State / Event / Effect

- State 是页面可重建的事实快照，内部可变 Flow 不向外暴露；更新使用不可变对象，Reducer 不做 IO、不启动任务、不发副作用。列表提交新快照，不原地修改已提交项。
- 同一事实只有一个可写来源；互斥计划用 enum/sealed 分支承载各自的输入、步骤和游标，展示属性从中派生。新增阶段若要反复同步多份字段，按 [结构复核](architecture-review.md) 收敛，而非继续增加重置清单。领域推进/合法性规则可提为 model 的纯函数，任务身份和生命周期仍由执行者负责。
- Event 表达用户意图；Effect 表达由 UI 执行的一次动作。渲染 State 不触发请求、导航或 Toast，避免重新订阅重做动作。
- 编辑草稿、服务端确认值和提交中状态分别表达；失败不能把未提交内容伪装成已保存。乐观更新必须定义回滚与冲突处理。
- 重要业务完成事实进入 State/持久化记录；Channel 不是“恰好一次”交付保证。支付结果、文件导出完成等需要可恢复核对，不能只靠一次 Toast 或导航 Effect。
- 导航/权限等需要防止重做的动作带可核对的操作 ID；需要确认消费时明确确认和重放机制。不要让多个消费者竞争同一 Effect Channel。

## 并发必须按动作选择

| 场景 | 默认考虑的策略 | 必须说明的边界 |
|---|---|---|
| 搜索、筛选、切换详情 | 最新输入替换旧请求 | 取消旧 Job，并核对请求代次、查询条件及会话；旧结果不得覆盖新状态 |
| 提交、删除、支付 | 单次进行或按业务串行 | 提交中禁用对应操作；服务端幂等与客户端防连点分别处理 |
| 独立区块加载 | 可并行 | 分别记录结果和失败；某区块失败是否取消其他区块由业务决定 |
| 同一列表翻页 | 同一条件下一次一个 | 刷新/筛选后旧分页失效；成功后才提交页码/游标 |
| 同一资源下载/生成 | 合并相同任务或显式排队 | 资源标识、用户作用域、输出所有权和取消者明确 |

- 取消是协作式的，部分 SDK/服务端不会停止；每次提交结果前仍校验任务是否属于当前请求、账号和环境。仅 `job.cancel()` 不足以保证结果顺序。
- 捕获普通失败时先放行 `CancellationException`；直接对挂起逻辑使用 `runCatching` 必须显式保留取消语义。不吞取消、不把取消显示成失败。
- ViewModel 默认在主线程编排；阻塞文件/数据库工作由数据实现选择 IO，CPU 密集转换选择合适调度器。不要用一个全局 IO 启动器掩盖线程要求。
- `finally` 用于释放资源、结束本任务占用；更新公共 loading 前核对任务身份，不能让旧任务的 finally 清除新任务状态。
- 连接状态只是提示，实际结果以请求为准；不能把“网络可用”当成功，是否允许缓存/离线操作由业务决定。

## 列表、搜索与流式内容

- 明确首屏空、首屏失败、刷新中、刷新失败、追加中、追加失败、无更多的差别。已有内容是否保留写入 Spec，刷新失败不默认清空列表。
- 查询条件形成一次快照；刷新建立新代次，分页结果只合并到同一代次。下一页游标/页码仅在成功且结果仍有效时推进，失败重试原页。
- 稳定 ID 来自数据语义，不能用列表位置替代；重复、删除、排序与本地编辑的合并规则来自当前协议。DiffUtil 的内容比较包括实际展示字段。
- 流式协议说明增量/全量、消息序号、完成标记、断线重连、取消及部分结果保留；分片不是独立业务成功。解析不能假设一次网络读取就是一个完整消息。

## 错误与恢复

- 分开传输失败、协议/解析失败、业务拒绝、鉴权失效、用户取消。保留可诊断的 code/requestId/cause，由业务映射语义，再由 UI 映射本地化文案。
- 网络拦截器处理传输共性，不直接切账号、清数据库或弹页面。鉴权失效交由会话协调者去重处理，并使旧会话任务失效。
- 重试区分可重试性、次数和退避；持续任务需要说明进程重启后如何恢复。上传、扣费等有副作用操作不得无限自动重试。
- ViewModel 只覆盖配置变化的部分恢复。进程死亡后的小型查询条件/编辑标识可用 SavedStateHandle；长期草稿/任务进度进入持久化，别把大对象或敏感令牌放 Bundle。
- 当前基类没有 SavedStateHandle 工厂支持；需要时先补齐 CreationExtras/工厂传递链，再登记真实用法，不能假定已存在。
- 账号/环境切换取消旧任务、释放旧依赖、切换数据作用域；迟到响应和回调不能写入新作用域。具体持久化见 [存储规则](file-storage-rules.md)。
