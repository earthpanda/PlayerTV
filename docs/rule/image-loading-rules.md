# PlayTV 图片加载与 UI 绑定规则

本文件维护运行时图片从来源到目标 View 的统一行为。类的唯一目录与命名见 [数据契约](data-contract-rules.md)，默认库与实际启用状态见 [依赖目录](build-dependency-catalog.md)。启用 image 时提供 `ImageLoader`/`ImageLoadOptions`；实际 API 和支持范围必须查 [组件目录](ui-component-catalog.md)、能力说明与源码。设计资产提供方式只在 [项目约定](project-conventions.md) 维护。

## 调用与边界

```text
Repository 提供图片来源/业务资源标识
  → ViewModel 保存到 State
  → Activity/Fragment/Adapter 绑定目标 ImageView
  → support 的 ImageLoader 调用图片 SDK
  → 目标显示结果，必要时回调当前绑定的加载状态
```

- 普通页面统一经过图片入口，不在各 Adapter 里分别创建 Glide RequestOptions。支持普通、圆形、圆角和 clear；选项优先表达项目自己的技术类型，不直接暴露 Glide 的缓存枚举。
- 加载入口只负责加载、变换、目标生命周期与诊断；不读取全局业务账号、不发业务请求、不跳转登录、不 Toast。确有鉴权/资源地址解析时由 model 提供业务信息，由 app 注入配置。
- 公共参数使用明确来源类型或 String/Uri/DrawableRes 等重载，避免一个 `Any?` 默默支持任意类型。Bitmap/Drawable、SDK RequestManager/Target 不进入 model 的 State 或 Contract。
- 普通图片局部加载中/失败由 View 或目标回调处理；只有业务交互确实依赖图片就绪时才按稳定 itemId 更新 State，不把整页接口结果改成失败，也不把每个解码回调都做成 Effect。

## 每次绑定都完整覆盖旧目标

1. 新地址加载要替换同目标的旧请求；空白地址、null、隐藏图片分支同样必须处理旧请求和旧 Drawable，不能写成“地址非空才 load”而留下上一行图片。
2. 明确区分：loading 占位、网络/解码 error、无来源 fallback。选项未指定图像资源时，默认取消旧请求并清空目标，不使用随机系统图或自动生成资源补齐。
3. 列表每次 bind 都设置完整的来源、可见性、裁剪和选项；不能依赖上一条数据的 scaleType、圆角或占位。DiffUtil 内容比较包含图片来源以及影响展示的版本字段。
4. 默认在列表 `onViewRecycled` 清理目标请求和自定义监听；复用时必须正确重绑。临时 detached 不等于永久回收，不在每次 detached 都全局清缓存。
5. 自定义监听若要更新 UI/State，核对 itemId/请求绑定代次和目标生命周期；替换后的旧回调不得更改新行。普通 `into(ImageView)` 优先使用 SDK 的目标替换机制，不额外制造后台 Scope。

## 生命周期、大小和变换

- 从当前页面/目标获取 SDK 的生命周期范围，不用 Application 作用域替代所有 View 请求。Fragment view 销毁时清除该视图持有的目标/监听；自定义 Target 必须有明确 clear/dispose。
- UI 入口和 clear 在主线程调用，解码/磁盘/网络交给 SDK，不在 ViewModel 手工下载解码大图。
- 按目标可见尺寸解码，默认使用 SDK 的目标尺寸测量；确需 override 时填写像素宽高。列表缩略图不默认请求原图尺寸，不为常规加载申请存储权限。
- 技术选项单位显式为 `widthPx/heightPx/cornerRadiusPx`；页面先用项目已有 pt 换算入口转换，图片工具不猜设计宽度、不重复缩放。
- 明确 `centerCrop/fitCenter` 等缩放策略；圆角需要裁剪时显式组合变换，不能以仅添加 RoundedCorners 假定同时实现 centerCrop。圆形与圆角互斥，非法尺寸在入口校验。
- 不默认头像一定圆形、卡片一定圆角；工具提供能力，具体选择来自页面设计。GIF/SVG/动效需要相应解码能力时再登记依赖，不假定普通静态图片配置支持所有格式。

## 地址、鉴权和缓存

- 默认允许项目声明的 HTTPS 图片来源；相对路径在 model 的映射/资源解析处根据明确资源基址解析，support 不拼业务域名。未经声明不把 HTTP、file、content 等当作可互换的远程 URL。
- 保留签名 URL 的原始编码和参数，不为缓存命中删除签名或过期参数。过期需要业务解析时，通过 model 的受控资源入口更新，不由图片工具无限重试接口。
- 公共图片可使用 SDK 的内存/磁盘缓存默认策略；图片内存/磁盘缓存属于 SDK 管理的应用缓存，不请求相册权限，也不把普通展示当用户下载保存。
- 私有图片必须在接入时明确缓存隔离和退出清理策略。相同 URL 可能随账号/环境返回不同内容，不能只用 URL 作为共享缓存标识；必要时包含非敏感作用域与内容版本，或关闭相应缓存。
- 自定义缓存 key 不包含 Token、Cookie、签名全文等秘密；账号变化后的旧目标、缓存与回调按本项目作用域策略处理。不能为提升命中率强行合并不同用户的资源。
- SDK 自带图片传输可用于公共图片，不必强行共用 API 客户端。需要自定义超时、受控 Header 或传输诊断时接图片传输适配器并登记额外依赖；禁止把 API 的全局鉴权/业务拦截器直接套到所有图片域名。
- 不在每次失败、刷新或 bind 时全局清缓存。磁盘清理按 SDK 的线程要求执行，清除目标、失效单资源和清理全缓存是不同动作。

## 失败可追踪

记录加载操作/安全资源标识、错误类别、目标尺寸和可用的状态码，不打印完整签名 URL、敏感本地路径或图片内容。空来源是明确 fallback 分支，不默认按网络错误刷 WARN；页面退出/旧请求替换的取消不报失败 Toast。

标准入口应能提供可选的成功/失败监听；监听不持有已销毁的宿主，错误信息不能只剩无法定位的 `false`。SDK 异常仅在技术封装内部使用，公开监听提供可解释的技术结果，不把 Throwable.message 原样展示给用户。

## 最小验收场景

- A 图片开始后立即绑定 B，最终只能显示 B；A 的迟到回调不能污染 B。
- 已有图片后绑定空地址、加载失败或隐藏图片，旧图不会残留；三种分支行为可区分。
- 列表快速滚动和页面退出后不回写旧目标，不持有旧 Binding；目标按展示大小加载。
- 图片失败不清空接口成功的列表，重试范围明确；网络请求日志与图片失败能分别定位。
- 有私有图片或账号/环境切换时，验证跨作用域缓存和旧请求隔离；未交付这些能力时明确不支持。

实际样例与执行状态写入功能 Spec，不把本文列出的场景当成已运行通过。公共实现交付还需依赖、初始化、资源/R8、实际调用和组件登记，不能只增加一个扩展函数就声明完成。

当前统一入口及来源/形状/缓存/线程限制见 [公共基础](common-foundation.md) 与本项目启用的 image 能力说明；未启用时不生成入口。调用示例只供静态阅读和授权后的验证，不代表运行已通过。
