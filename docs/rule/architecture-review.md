# 结构复核与规则验证

职责和目录的唯一判定在 [数据契约](data-contract-rules.md)，查找先例及讨论顺序在 [AGENTS](../../AGENTS.md)。本文件规定何时复核结构、如何验证规则；不增加第五个模块、固定调用层数或通用业务引擎。

## 何时重新检查结构

出现以下任一信号，在本次改动范围内复核职责，并在已有 Spec 的封装边界/完成状态记录结论：

- 新增一种业务阶段，需要同时修改多处选择、重置、完成和恢复分支。
- 同一事实存在多份可写字段；互斥方案同时保留多个计划、游标或布尔组合。
- ViewModel 开始实现领域算法，或 View 开始决定业务成功、数据写入和冲突规则。
- 新增跨页面/跨进程持续工作、账号作用域或资源所有者，原生命周期假设不再成立。
- 准备新增模块、公共基类/Manager、SDK，或复制第二份同语义公共入口。

先指出具体重复事实/责任，再选择局部函数、独立业务对象、互斥状态或真实共享能力；若现有职责仍清楚，可保留并说明依据。文件行数仅用于定位，不是自动拆类门槛；不要为通过复核制造空转发或全局万能引擎。

## 少量正反例

| 场景 | 合理处理 | 应避免 |
|---|---|---|
| 多个纯计算规则组成一条路线，没有网络和数据库 | model 的业务动作/Planner 组合规则，计算实现选择 Default；ViewModel 管事件和过期结果 | 因为没有数据源，把算法堆进 ViewModel 或伪装成 Repository |
| 多种互斥编辑/教学计划 | 一个 sealed 计划分支携带自身输入、步骤和游标；展示字段从它派生 | 多份可写计划/游标，每新增一种都在所有重置路径手工清空 |
| 相机、顶点、命中点和拖动预览 | app 的渲染/输入实现内聚技术类型，业务契约仅表达已确认动作 | 看到 data class 就移入 model；把 Matrix/View/触摸回调塞入业务 State |
| 请求并展示一页数据 | ViewModel 调用已有 Repository；按实际语义增加映射 | 每个接口一律创建 UseCase、Manager 和空 DataSource |
| 页面退出后继续上传，且进程重建要恢复 | 按 Service/任务和存储规则确定任务记录、执行者、重试与所有者 | 给页面 Job 换成全局 Scope 就声称已支持持久任务 |

## 确定性检查入口

在工程根目录运行 `python tools/check_architecture.py`，只读检查四模块的字面 Gradle 工程依赖、Kotlin 显式 import 方向，以及业务数据/Contract/状态/UseCase 对 UI 宿主类型的直接导入。结果含规则 ID、文件和行号；退出码 0 为所支持检查通过，1 为违规，2 为配置或语法覆盖不足、需要人工核对。没有静默豁免清单。

脚本使用标准库和文本扫描，不调用 Gradle、编译器或 Android lint。它不解析完整 Kotlin/Gradle 语义，不能证明完全限定名、反射、别名构建逻辑、线程、取消、状态互斥、持久化或资源释放正确。规则冲突和未覆盖的写法按 AGENTS 判断，不通过扩大忽略范围制造“通过”。后续可接入 CI，但本次入口不等于 CI 已启用。

结构复核仍需人工对照：唯一可写事实、任务身份/取消、已提交状态与动画预览、所有者/关闭，以及本功能确实涉及的恢复与冲突。组件和参考索引只证明路径可发现；测试、构建与真机交互分别记录。

## 用真实业务验证并回补

按“先修权威规则 → 修改对应业务 → 检查行为 → 回补先例与限制”迭代。每轮记录：暴露的问题、适用的规则位置、实际改动文件、执行过的验证及仍未覆盖的边界。实现偏差修代码；规则歧义修唯一来源；公共能力缺口先补模板；业务差异留功能 Spec。

一个样本通过不代表整个骨架已验证。下一类真实业务优先覆盖前例未涉及的持久任务、复杂编辑或数据冲突，选择已有真实需求，不为验证框架发明业务。验收至少对应以下一组：

| 验证维度 | 要观察的行为 | 对应规则 |
|---|---|---|
| 持久任务 | 页面退出、进程重建、重复启动/停止、失败重试，任务记录与运行者一致 | [Service 与通知](android-service-notification-rules.md)、[Manager](manager-lifecycle-rules.md)、[存储](file-storage-rules.md) |
| 复杂编辑 | 草稿/已保存分开，取消和撤销、并发提交、重建恢复不误保存 | [业务开发](business-development-rules.md)、[存储](file-storage-rules.md) |
| 数据冲突 | 旧版本晚到、本地未提交修改、事务回滚、重试后无重复副作用 | [数据库与同步](database-sync-rules.md) |

还没有真实需求或授权运行的维度标为“待验证”，不能拿魔方算法回放、夹具或文档齐全替代上述验收。
