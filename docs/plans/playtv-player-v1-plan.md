# PlayTV 首版播放器计划

状态：计划，尚未开始实现。更新日期：2026-11-26。

## 目标和范围

首版让用户在 Android TV 上使用遥控器播放普通网络视频和公开直播频道。支持以下来源：

1. HTTP/HTTPS 视频直链，包括 MP4、可直接访问的 GitHub 文件及 Release 媒体地址。
2. HLS `.m3u8` 点播和直播。
3. IPTV `.m3u` 频道列表，列表中选择频道后播放对应视频流。
4. 国家/地区、新闻、电影等分类的频道列表；电影分类可能是直播频道，不承诺影片点播库。
5. MPEG-DASH `.mpd` 点播和直播。

上面是**同一个首版的目标范围**，按下文顺序分阶段完成，不把 DASH 或分类浏览默默移出首版。各项实际可用性取决于媒体编码、服务器和目标设备；不承诺播放互联网上所有来源。

首版聚焦播放、暂停、停止/返回、点播进度与定位、缓冲/错误提示、频道选择和基本分类浏览。直播不可定位或时长未知时不能套用点播进度。暂不做倍速、多音轨或多声道选择、字幕选择、截图/录制、A–B 循环、后台播放、DRM、账号和下载；正常有声视频仍须验证声音。后续需求另行规划，不要求首版实现这些控制项。

此文件是执行计划，不替代开发前的正式功能 Spec。按项目规则补齐业务决策和设计后再编码；本计划中的待实现项不代表已交付。

## 当前基线与依据

- PlayTV 当前入口是技术样例 `SampleActivity`；未实现播放器页面、播放调用、频道列表和 TV 遥控器体验。可复用状态页面、MVI、AndroidX ListAdapter，真实入口见[组件目录](../rule/ui-component-catalog.md)。
- app 声明 `com.ai.media:playback-android:0.1.0`，从本地 Maven 仓库解析；2026-11-26 核对 AAR SHA-256 为 `fb04deaa5f3bb147915dcf5da98bb74ffcb9b7500f303b90df20d4e95077453d`，与[依赖目录](../rule/build-dependency-catalog.md)历史记录一致。该版本当前包含 arm64-v8a、最低 Android 26，目标电视设备及其他 ABI 尚未确认。
- SDK 发布源码提供 HTTP/HTTPS `loadNetwork`，明确不自动跟随重定向、不自动重试；HTTP 明文受宿主网络安全策略限制。SDK Manifest 声明 INTERNET。SDK 底层使用 GStreamer，但**HLS 和 DASH 是否由当前发布产物完整支持尚未验证**，不依据底层名称推定可用。播放器技术契约参考[媒体接入说明](../reference/media/README.md)。
- 历史 debug 包曾构建并安装到 vivo V2244A / Android 14；没有在 PlayTV 中调用播放器、进行电视播放或遥控器验收。本次只核对文档、Gradle 声明与发布产物；没有构建、运行测试或播放验证。
- 按用户要求，只读参考了 JustSoSo 的 `docs/plans/local-player-evolution.md`、`docs/plans/media-kernel-sdk-plan.md` 与 `docs/feature/mediaplayback/test-media-playback.md`：采用阶段化交付、SDK/App 分工、旧路径回归和证据记录；历史结果不作为 PlayTV 本轮通过记录。其倍速、音轨、录制等功能不自动进入本首版。

## 执行规则：完成一个，再进入下一个

按阶段 0 → 1 → 2 → 3 → 4 → 5 顺序推进。每阶段分别完成需求/Spec、实现、针对性单测、相关旧行为回归和本阶段设备验收，记录实际结果后再进入下一阶段。失败先查因、修复、按影响重新验证；关键验证缺失时标为阻塞或待验收，不把编译或单测通过写成播放完成。可独立准备后续测试数据，但不把未验收的阶段标为完成。

阶段记录至少包含：代码/SDK 版本与 AAR 摘要、设备与 Android 版本、测试命令及结果、每个实际场景与有效轮次、日志/截图等证据位置、失败及修复、剩余限制。历史验证与本次结果分开。状态统一为：未开始、进行中、待验收、已完成、阻塞；此计划中现在均为**未开始**。

每阶段的单元测试覆盖真实业务规则及失败边界，不只验证模拟对象的调用次数；播放器原生管线和画面、声音、焦点、释放还需要设备验证。普通可重复专项默认至少 **3 次有效轮次**；修复按项目 AGENTS 的影响等级选择 3/10/20/30/50 次，并记录依据、实际次数和失败证据。环境在到达目标场景前失败不计有效轮次。测试不会证明零缺陷；发现影响基本使用的问题先修复并重验。

Gradle、单元测试、构建及设备操作均按项目授权边界执行；测试任务必须实际有测试用例且记录执行数量和失败/跳过，不能用空任务或历史结果冒充通过。构建优先 `--no-daemon`，按项目规则核对并仅清理由本次构建启动的进程。

## 阶段 0：锁定首版边界与验收环境

**交付**：建立正式功能 Spec，明确以下内容；不把计划中的建议自动当作已确认业务事实。

- 确认播放入口：用户如何输入/选择直链和频道列表、默认来源及分类入口；区分 GitHub 直链、Release 地址、普通网页和仓库目录。首版是否需要浏览任意 GitHub 仓库内容尚未确定，不把通用仓库搜索当作现有能力。
- 确认 TV 设备型号、系统版本、ABI、遥控器及必要的测试网络；至少选定一台目标 TV/盒子。手机可辅助调试，不能代替电视焦点和遥控器验收。
- 确认正式页面设计、设计宽度、本地资产和入口/返回路径；缺少设计或必要资产按项目规则处理。若先建立技术验证页，要明确其源集和定位，不能把它当正式页面验收。
- 按实际能力写清直播/点播状态、输入校验、失败恢复、重复操作、播放资源所有者、进程重建以及来源保存需求。持久化、图片、后台 Service 和其他依赖不因本计划自动启用；缺少真正必要的业务决定时只暂停依赖该决定的部分。
- 建立确定性本地 HTTP 测试源及已授权的公开样例清单，固定响应、视频与列表数据；公网地址可辅助检查，不能作为唯一验收依据。检查 HTTPS、跳转、Range、失败及请求记录的可观测性。

**单测与验收**：列出每阶段的测试对象、运行命令、设备和证据路径；确认各单测可验证业务结果、错误与取消。检查当前 AAR/native 内容、实际插件和公开 API，并记录不能静态确认的能力；只有环境与必要决策具备才开始对应实现。

## 阶段 1：MP4 直链和基础播放器

**交付**：

- 将页面/Surface 与现有 SDK 正确接入；用户选择有效来源后播放有声 MP4，展示加载、播放、暂停、结束及可恢复错误。点播在 SDK 确认可定位时提供进度和定位，暂停后定位不改变用户暂停意图。
- 返回/离开时停止并释放，切源时取消旧请求，旧回调不能覆盖新来源。音频焦点、Surface 及宿主生命周期按 SDK 契约处理；不新增后台播放。
- 支持实际 HTTP/HTTPS 媒体直链；GitHub 文件/Release 地址验证真实响应。SDK 当前不跟随 3xx，需在合适的网络/SDK 层设计受控跳转，限定跳转次数与目标、取消、HTTPS 验证及跨域/明文策略；不能关闭证书验证或全局允许明文。纯 GitHub 网页、需要登录或授权的资源给出明确失败，不伪装成可播放。
- 失败、缓冲中仍可返回；对不支持 Range 的来源明确定位能力，不能承诺一定可以拖动。日志不得泄露 URL 查询凭据或 Cookie。

**单元测试**：输入/来源识别；跳转链正常、相对 Location、循环/超限、非法协议或不允许的明文、取消及错误映射；播放状态与用户暂停意图；快速切源/停止后的迟到结果隔离；可定位和不可定位状态。网络相关测试使用可控服务，不依赖公网。

**设备验收**：受控有声 MP4 和公开 MP4 分别验证画面、声音、暂停/恢复、定位、播放结束、返回和重新进入；验证实际 GitHub 可访问地址及跳转、不可用/错误地址、断网或慢网、切源和释放。遥控器焦点与返回行为在目标 TV 检查。按需同时回归技术样例及共享 UI 基础，记录本次实际结果。

**完成条件**：单测通过，目标设备上述普通与失败场景通过，至少 3 次有效基础播放/退出；无本阶段已知阻断普通使用的问题，证据已记录。

## 阶段 2：HLS 点播与直播

**交付**：先核实当前 SDK 发布产物实际具备的 HLS 插件、网络行为与设备播放结果；不足时在独立 PlaybackSDK 的实际缺口层补齐并发布可追溯的新版本，PlayTV 再接入。避免仅凭解封装器存在就宣称支持完整播放。

支持 HLS 点播和直播；清单可引用相对地址、多码率变体和媒体分片。直播按实际能力显示状态；缓冲、暂停意图、切台/切源、停止和退出必须可靠。无需首版提供手动清晰度选择，若 SDK 自动选择则验证实际行为。每一层请求仍受已确定的跳转、HTTPS 和明文策略约束。

**单元测试**：来源分类、直播/未知时长 UI 状态、缓冲与暂停意图、切源竞争、错误映射和 URL 解析/策略中由本项目负责的部分；SDK 新增可确定的状态/协议逻辑也须覆盖。不能用业务层模拟取代原生播放验证。

**设备验收**：受控 HLS 点播、持续更新的直播和多码率样本各验证画面/声音；验证播放清单及分片错误、断网/恢复或用户重试、快速切源、停止和退出；点播定位与不可定位直播分别检查。回归阶段 1 的 MP4 和 GitHub 跳转。

**完成条件**：上述单测、TV 实播和旧路径回归通过，点播/直播各至少 3 次有效播放与退出；未查明的问题保留风险并按影响决定是否阻塞。

## 阶段 3：IPTV 频道列表与选台

**交付**：按确认的入口加载 HTTP/HTTPS M3U 频道清单，解析有效频道及名称、分组等实际提供的字段；选择频道后使用阶段 1/2 的播放能力。区分 IPTV 频道列表和单路 HLS 清单，结合内容而非只看扩展名。支持相对 URL、UTF-8/BOM、空行与常见扩展字段；未确认的来源扩展逐项处理，不默认为全部兼容。

下载和解析需设置明确的字节、行数/频道数、跳转及超时上限，后台执行且可取消；上限在 Spec 中依据目标设备和样本确定。无效条目与整份列表不可用分开，部分可用时保留可播放条目并说明问题；新列表加载失败时如何处理已有列表在 Spec 确定。快速选台使用最新请求，旧流及回调不能接管新频道。

**单元测试**：不同换行、BOM、中文名称、`#EXTINF` 字段、分组/缺失字段、相对链接、重复或无效条目、空文件、损坏及限制超出；HLS/频道列表识别；加载失败、取消、快速切换及旧结果隔离。测试应检查实际解析结果和保留策略。

**设备验收**：受控列表和公开列表分别加载、遥控器选台、快速切台、失败频道切换到可用频道；验证大列表下焦点与滚动、加载失败、退出及资源释放。回归 MP4、HLS 点播与直播。

**完成条件**：解析与状态单测通过，设备上列表、切台及失败恢复通过，至少 3 次有效加载/切台/退出，旧路径回归通过。

## 阶段 4：分类浏览

**交付**：在已确认的来源和分类范围内，复用频道列表加载/解析能力，提供国家/地区及内容分类入口；从分类进入频道列表并播放，返回时保持合理焦点。分类数据以来源实际提供的信息为准，不虚构节目、海报或影片详情。图标加载若纳入首版，先按项目图片规则核对实际能力与失败占位；不得因计划假定图片 SDK 已接入。

**单元测试**：分类到列表的映射、缺失/空分类、切换分类时旧结果隔离、加载失败和返回状态；保持阶段 3 的原列表解析断言。

**设备验收**：切换至少两个来源实际提供的分类，进入频道、播放、返回并检查焦点；验证空分类和加载失败，回归阶段 3 的选台。

**完成条件**：单测、目标电视上的分类/选台与失败场景通过，至少 3 次有效进入/返回，既有播放与选台回归通过。

## 阶段 5：DASH 点播与直播

**交付**：核对当前 SDK 实际 DASH 插件和播放能力；存在缺口则先在 PlaybackSDK 补齐、发布可追溯产物，再由 PlayTV 接入 `.mpd` 点播与直播。使用与 HLS 一致的播放状态、生命周期及错误语义；无 DRM 样本作为首版基线。

**单元测试**：来源识别、DASH 点播/直播状态和错误映射、请求取消及切源隔离；SDK 若新增可测的协议/状态规则，同步增加对应单测。旧 HLS/MP4 和列表断言保持。

**设备验收**：受控 DASH 点播及直播检查画面、声音、可定位性、缓冲、失败、切源、停止及释放；各至少 3 次有效播放/退出。回归阶段 1–4 的代表性 MP4、HLS、频道列表和分类选台。

**完成条件**：单测与设备专项通过，旧路径回归通过，版本和证据齐全；至此才可进入首版整体验收。

## 首版整体验收

- 所有阶段完成且结果可追溯；在目标 TV/盒子使用遥控器完成直链播放、直播选台、分类浏览与 DASH 播放，并检查普通有声视频的画面、声音、暂停/恢复、返回和资源释放。
- 使用受控服务覆盖断网、缓慢响应、跳转失败、无效媒体、无效列表、快速切源和退出；发生问题须保留证据、分析根因、在所属层修复并重跑受影响的新旧场景。
- 对 PlayTV、PlaybackSDK 的变更分别记录责任边界、版本/产物、单测、构建、设备结果；SDK 曾有的其他能力若被底层改动影响，按实际调用链和发布契约回归，不能因为首版不展示对应按钮就忽略共享路径。
- 检查最终差异、架构约束与项目规则。未完成的设备、场景或兼容性明确列出，不能声称“无明显 bug”或首版已完成；所有关键项通过后仍只对已测版本、场景和设备给结论。

## 待明确事项

进入相应阶段前确认：目标电视设备/ABI；正式设计和设计宽度；来源输入方式、内置来源及分类；是否保存用户来源/进度；对 HTTP 明文源的产品策略；是否需要浏览任意 GitHub 仓库。以上不会阻止先准备不依赖这些选择的调查和测试设计，也不授权擅自添加账号、后台播放或其他高级功能。
